# Сборка prompt карточки

Читай при изменении `cards/CardPromptCompiler` или переноса оформления шаблона.
Запуск и сохранение snapshots — [CARD_GENERATION.md](CARD_GENERATION.md).

## 1. Источники данных

- Фактический текст — актуальный ProductAnalysis.description под блокировкой Product.
- В режиме шаблона используются description, snapshot общего recipe/reference и выбранного сценария, окончательная idea.
  ProductAnalysis.title/idea/generationPrompt и пользовательский prompt не добавляются.
- Без шаблона используются description и явно переданный пользовательский prompt.
  Idea анализа не подставляется автоматически.
- `analyses/GenerationPromptBuilder` собирает отдельное read-only поле анализа
  generationPrompt; оно не является prompt первой карточки. Не объединяй два builder.
- Исходное изображение передаётся модели вместе с текстом; reference — вторым изображением.

## 2. Шаблонный prompt

fromTemplate проверяет, что recipe — JSON object с schemaVersion=1; неверный/неподдерживаемый
recipe даёт `422 TEMPLATE_NOT_READY`. Это не полная валидация authoring-схемы.

Секции: factual description → scene → composition → lighting → style → palette →
правила двух изображений/текста → avoid → требование готовой карточки.
Добавляются непустые строковые секции и строковые элементы массивов.
Recipe описывает оформление, а не новые факты о товаре.

Сохраняй смысловые требования:

- Image 1 — исходный товар: сохранять идентичность, геометрию, цвета, бренд и видимые надписи.
- Image 2 — reference композиции/стиля: заменить демонстрационный товар исходным,
  адаптировать layout под запрошенное соотношение сторон с сохранением выравнивания,
  взаимного расположения блоков и визуальной иерархии; ориентация reference не фиксирована.
- Сохранить расположение/иерархию заголовков, характеристик и плашек; переписать overlay-текст
  по description, согласованно с фото и на языке description. Блок без подтверждённых сведений опустить.
- Не копировать название, бренд, claims, цены и варианты цветов reference; не добавлять
  отсутствующие на исходном фото части комплекта, товары или ракурсы.
- Палитра reference применяется к фону/декору; она не перекрашивает товар и не задаёт его варианты.
- Вернуть одно готовое изображение без выдуманных цен, брендов, свойств и преимуществ.
- В обоих режимах весь видимый исходный товар и overlay-текст должны помещаться
  с полями минимум 5% от каждого края. Длинный текст переносить, шрифт уменьшать,
  блоки переставлять без обрезки/растягивания; сохранять место над заголовком и под товаром.
  Конкретные пиксели canvas добавляет transport из GenerationRequest по [IMAGE_GENERATION.md](IMAGE_GENERATION.md).

Для шаблонов с надписями не добавляй общий запрет text/headings/badges в avoid:
он конфликтует с сохранением блоков. В стартовых recipe миграции 010 такие ограничения
ещё есть; заменяй нужный recipe новой миграцией по [TEMPLATES.md](TEMPLATES.md).

## 3. Пользовательский prompt и ограничения

fromUserPrompt добавляет factual description, User visual direction, сохранение товара
и требование одного изображения без выдуманных фактов. Reference и его правила не добавляются.

Итоговая строка в обоих режимах ограничена 8000 символами; превышение — `422 VALIDATION_ERROR`.
Даже контрактный prompt длиной 8000 может не поместиться после добавления description и инструкций.

Компилированный prompt хранится в Card, но не выдаётся через Card DTO и не логируется.
Не принимай технический prompt/recipe от UI в обход сборки на сервере.

## 4. Сценарии серии

Реализована по [docs/card-series-tasks.md](../../docs/card-series-tasks.md).
`fromVariant` сохраняет перенос layout первой обложки; для следующих позиций заменяет
composition и требования расположения reference на сценарий. Подготовленные варианты —
[card-variants.json](../../assets/templates/tpl_fashion_hero/card-variants.json).

- Различай пользовательскую `idea` отдельной карточки и технический `prompt`.
  Новая идея дополняет сценарий выбранного шаблона; это не смешивание нынешних
  взаимоисключающих источников templateId/prompt.
- В шаблоне хранится стартовая идея; backend использует окончательный пользовательский
  текст или defaultIdea, если редактированный текст не передан. Пустую явную идею отклоняй.
- Окончательная идея меняет замысел/акцент/композицию; стартовые инструкции сценария не
  должны одновременно требовать несовместимое расположение блоков. Общий стиль,
  фактические ограничения и идентичность товара сохраняются.
- Первая обложка сохраняет нынешнее перенесение layout. Для последующих вариантов
  reference задаёт стиль, а композицию задаёт сценарий с учётом окончательной идеи.
- Для явно запрошенного крупного плана последующей карточки требуется отдельное правило:
  допустима только действительно различимая область исходного товара, с запасной
  композицией целого товара при недостатке данных. Текст и выбранная область сохраняют
  поля 5%; запрет обрезки ответа при transport-нормализации не меняется.
- Не выдумывай фактуру, швы, маркировку, качество, состав, размеры, ракурсы и комплект
  ради выполнения сценария. Применимость примера проверяется по товару пользователя.
- Не используй ProductAnalysis.idea/generationPrompt как сценарий следующей карточки.
  Готовый технический prompt и recipe остаются серверными данными.
