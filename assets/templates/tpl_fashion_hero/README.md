# Пример шаблона «Крупный заголовок и характеристики»

Готовый пример для категории **«Одежда и обувь»** (`cat_fashion`). Миграция `011-fashion-template-example` заменяет заглушку существующего `tpl_fashion_hero`, сохраняя его категорию и порядок. Остальные шаблоны она не изменяет.

![Превью шаблона](reference.webp)

| Параметр | Значение |
| --- | --- |
| Файл для загрузки | `assets/templates/tpl_fashion_hero/reference.webp` |
| Bucket в MinIO | `user-images` по умолчанию; если задан `MINIO_BUCKET`, использовать его значение |
| Ключ объекта в MinIO | `templates/tpl_fashion_hero/reference.webp` |
| Content-Type | `image/webp` |
| Размер | `384×512`, `29704` байта (около `29 КиБ`) |
| Asset ID | `asset_tpl_fashion_hero_ref` |
| Template ID | `tpl_fashion_hero` |
| Recipe и метаданные | [Миграция 011](../../../src/main/resources/db/changelog/changes/011-fashion-template-example.yaml) |

При стандартной конфигурации полный путь: `user-images/templates/tpl_fashion_hero/reference.webp`. Здесь `user-images` — bucket, а `templates/tpl_fashion_hero/reference.webp` — ключ объекта внутри него. Bucket задаётся настройкой `tovarika.storage.minio.bucket` через переменную `MINIO_BUCKET`; значение по умолчанию `user-images` одинаково для локального запуска и обоих Compose-файлов.

## Логическое разделение внутри bucket

В одном bucket используются отдельные папки для исходных фото, готовых карточек и шаблонов:

```text
user-images/
├── products/                         # исходные фотографии товаров пользователей
├── cards/                            # сгенерированные карточки
└── templates/                        # изображения шаблонов
    └── tpl_fashion_hero/
        └── reference.webp
```

В MinIO папки отображаются по префиксам ключей объектов. Загрузка файла с ключом `templates/tpl_fashion_hero/reference.webp` размещает его в соответствующей папке. При ручной загрузке можно заранее создать папки `templates` и `tpl_fashion_hero` через консоль MinIO.

Такое разделение уже предусмотрено: приложение записывает исходные фото в `products/`, результаты генерации — в `cards/`, а миграция примера ссылается на `templates/`.

## Как посмотреть в приложении

1. В консоли MinIO открыть bucket `user-images` (или переопределённый через `MINIO_BUCKET`), внутри него перейти в `templates/tpl_fashion_hero/` и загрузить `reference.webp`. При необходимости создать этот префикс. Префикс `assets/` и имя bucket в ключ объекта не входят.
2. Запустить обновлённое приложение: Liquibase применит миграцию `011-fashion-template-example` и свяжет файл с существующим шаблоном.
3. Открыть категорию «Одежда и обувь». У шаблона «Крупный заголовок и характеристики» появится это превью. Через API его можно найти запросом `GET /api/v1/templates?categoryId=cat_fashion`.
4. Загрузить собственное фото товара, дождаться анализа, проверить и при необходимости исправить описание, затем выбрать этот шаблон и создать карточку.

Для проверки реальной генерации приложение должно работать с настроенным `OPENAI_MODE=live`. В режиме `stub` каталог покажет загруженное превью, но результат генерации останется тестовой заглушкой.

Надписи «КОСТЮМ», «ДЕТСКИЙ», характеристики и цвета — демонстрационное содержимое reference. При генерации они заменяются данными товара пользователя; блок без подтверждённых данных опускается. Ракурсы и части комплекта из примера также не должны добавляться, если их нет на исходном фото пользователя.

## Подготовленные сценарии серии

[card-variants.json](card-variants.json) содержит 10 вариантов: первую обложку и девять
следующих карточек, с пользовательскими идеями, композициями и условиями показа деталей.
Это подготовленные authoring-данные; текущий runtime ещё не загружает их и поддерживает
только первую карточку. JSON не заменяет recipe миграции `011`.

Порядок реализации хранения, наполнения, API и UI, а также критерии проверки описаны в
[задачах серии карточек](../../../docs/card-series-tasks.md).

Изображение создано встроенным `image_gen` по приложенному пользователем образцу, затем уменьшено и сохранено в WebP для каталога. [Запрос создания изображения](generation-prompt.txt) сохранён для воспроизводимости; рабочий recipe находится в миграции.
