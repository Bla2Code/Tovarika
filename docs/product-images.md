# Дополнительные исходные фотографии

Товар хранит первоначальный исходник в `products.source_asset_id`, а все фотографии —
в `product_images`. Файлы остаются в существующем хранилище `assets`.
При принятии генерации выбранный исходник записывается в `cards.source_asset_id`.
Worker и retry используют это значение независимо от последующих загрузок.
Редактирование готового изображения по-прежнему использует bitmap текущей версии.

API: `GET/POST /api/v1/products/{productId}/images`; POST принимает multipart `image`.
`GenerateCardRequest.sourceAssetId` необязателен, без поля используется основное фото.
Проверяются принадлежность фото товару, формат, размер, декодирование и rate limit.
Загрузка не запускает AI и не меняет основное фото, анализ или настройки серии.
Лимит одной активной image job на проект сохраняется.

## Обновление с сохранением данных

Этот релиз рассчитан на остановку старой версии backend и её workers на время обновления.
В момент обновления не должно выполняться заданий. Новая версия применяет Liquibase
changeset `085-product-images`: создаёт коллекции из существующих основных фото и
заполняет исходники всех прежних карточек через проект и товар.
Записи и файлы сохраняются; повторная загрузка изображений не нужна.
У исторических записей без исходного фото поле остаётся nullable.
После применения миграции запускаются только новые backend/workers, затем обновлённый UI.
Смешанная работа старых и новых workers этим порядком обновления не предусмотрена.
