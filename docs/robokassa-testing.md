# Тестовая оплата Robokassa

В технических настройках магазина должны быть сохранены три разных адреса:

| Поле | URL | Метод |
| --- | --- | --- |
| Result URL | `https://tovarika.com/api/v1/billing/robokassa/result` | POST |
| Success URL | `https://tovarika.com/api/v1/billing/robokassa/success` | GET |
| Fail URL | `https://tovarika.com/api/v1/billing/robokassa/fail` | GET |

Используется домен интерфейса: Caddy проксирует `/api/v1/*` в backend.
Главная страница `https://tovarika.com/` не является обработчиком платежей.
Если поставить её в Result URL, подтверждение не попадёт в биллинг и
пополнение не отразится ни в балансе, ни в истории.

Алгоритм подписи — SHA256. Для тестовых платежей нужны именно тестовые
пароли магазина. Приложение передаёт `IsTest=1`; создание оплаты доступно
только при режиме `TEST` и для пользователей из `testUserIds`.
Секретные значения не следует сохранять в документации или репозитории.

## Что происходит после оплаты

1. Robokassa отправляет подписанное подтверждение на Result URL.
2. Backend проверяет подпись, номер заказа, его идентификатор и сумму.
3. В одной транзакции создаются начисление `package_purchase` и пакет Товариков,
   обновляются баланс и статус заказа. Ответ Robokassa — `OK` с номером счёта.
   Повторное уведомление не создаёт второе начисление.
4. Success URL возвращает пользователя на
   `/billing?payment=<purchaseId>&paymentReturn=success`.
   Fail URL возвращает на ту же страницу с `paymentReturn=fail`.
5. Интерфейс проверяет статус своего заказа. После подтверждения он показывает
   сумму начисления и срок действия, обновляет баланс, пакеты и историю.
   В истории появляется «Покупка пакета» с положительной суммой.

Возврат браузера сам по себе не подтверждает и не отменяет заказ.
Если серверное подтверждение ещё не пришло, интерфейс ожидает его и позволяет
обновить статус. Даже после Fail URL запоздавшее корректное подтверждение
должно начислить оплаченный пакет.

## Проверка после сохранения настроек

1. Авторизоваться тестовым пользователем и записать текущий доступный баланс.
2. На `/pricing?return=%2Fbilling%3Freturn%3D%252Fprojects` выбрать пакет 140 Т.
   Убедиться, что страница оплаты работает в тестовом режиме.
3. Пройти успешную тестовую оплату. После возврата должны появиться сообщение
   о подтверждении, прибавка 140 Т и одна строка «Покупка пакета» на +140 Т.
   «Всего использовано» при пополнении не увеличивается.
4. Обновить страницу: сумма и количество начислений не должны измениться.
5. Создать отдельную тестовую оплату и выбрать неуспех. Возврат должен вести
   на баланс с сообщением о незавершённой оплате, без начисления.

Платежи, созданные до исправления Result URL, не следует начислять вручную
по факту посещения Success URL. Для них необходимо корректное подписанное
уведомление Robokassa; для проверки новых настроек лучше создать новый заказ.

Официальное описание: [уведомления и переадресация](https://docs.robokassa.ru/ru/notifications-and-redirects),
[тестовый режим](https://docs.robokassa.ru/ru/testing-mode).
